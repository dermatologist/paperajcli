# NOTES

## Design Decisions

### Splitting Logic
The original `paperaj.sh` split files based on `\section` headers generated by Pandoc. The new requirement specified using explicit XML-like delimiters: `<paperaj-NAME> ... </paperaj-NAME>`.
- The CLI first converts the MS-Word file to Markdown.
- It then scans the Markdown for these delimiters.
- If found, it creates separate LaTeX files (e.g., `NAME.tex`) corresponding to each section.
- If no delimiters are found, it defaults to processing the entire document as `document.tex`.

### Pandoc Integration
The tool relies on `pandoc` being installed on the system.
- It uses `child_process.spawn` to invoke Pandoc.
- It avoids intermediate temporary files for the conversion process where possible, piping data between functions (logic streams), although Pandoc media extraction still requires writing to disk.

### Image Processing
- Images are extracted to a `media/` subdirectory within the output folder.
- The processor rewrites image paths to be relative (e.g., `media/image1.png`) so LaTeX compilers can find them.
- It preserves the custom caption handling logic from `images.py`, including support for `TWOCOLUMN` and `LATEXROTATE` flags in captions.

## Dependencies

- **Node.js**: >= 18.0.0
- **Pandoc**: Version 2.11 or later is required for media extraction and Markdown/LaTeX conversion.
- **OcLif**: The CLI framework used.

## Future Improvements
- Add a `--dry-run` flag to preview sections without writing files.
- Add support for custom delimiter patterns via flags.
- Bundle a WASM version of Pandoc to remove the system dependency (though complex for media extraction).
